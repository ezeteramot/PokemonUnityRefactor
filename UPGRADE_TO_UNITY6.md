# Unity 6 Migration Strategy

This repository targets legacy versions of Unity, including built-in GUI APIs (GUITexture, RenderTexture based screens) and a number of assets that have since been removed from the engine. Updating the entire project to Unity 6 requires systematic changes across code, scenes, prefabs, shaders, and asset pipelines. Because this refactor cannot be completed automatically within this environment, the following checklist captures the manual actions needed to complete the migration in a local Unity 6 editor.

## 1. Preparation
- Install Unity 6 LTS along with Android/iOS build support if mobile builds are required.
- Use the Unity Hub to create a copy of the existing project before upgrading.
- Ensure the project uses the **.NET Standard 2.1** or **.NET Framework** compatibility level required by Unity 6 (Player Settings > Other Settings).

## 2. Package and API Updates
- Replace deprecated `UnityEngine.UI` packages by enabling the `UIToolkit` package from the Unity Package Manager.
- Review all compile-time API changes using the Unity API Updater after the first Unity 6 import. Resolve any blocking compiler errors by replacing obsolete APIs with Unity 6 equivalents.
- Update scripting runtime assemblies to target `UnityEngine.InputSystem` if migrating from the legacy input API.

## 3. Asset Replacement Checklist
- **GUITexture/RenderTexture UI**: Convert each screen to a `UIToolkit` `UIDocument`. Use USS stylesheets for layout and styling and create `VisualTreeAsset` `.uxml` files inside `Assets/UI/`.
- **Materials/Shaders**: Upgrade legacy Standard shader materials to the Universal Render Pipeline (URP) shader graph equivalents. Install URP via Package Manager and run the Material Upgrade tool.
- **Animation Controllers**: Rebind animation clips using the Animator window to regenerate state machines compatible with the new rig import settings in Unity 6.
- **Audio**: Update `AudioMixer` assets to ensure they reference the correct output groups.

## 4. Scene-by-Scene Migration
1. Open each scene in Unity 6. Allow the automatic upgrade prompts to run.
2. Replace outdated prefabs with updated versions created in the new `Assets/Prefabs/` directory.
3. Bind UIToolkit documents to controllers using `UIDocument.rootVisualElement.Q<VisualElement>(...)` selectors.
4. Replace `OnGUI` code with UIToolkit event handlers and `VisualElement` interactions.

## 5. Testing and Validation
- Run play mode tests and integration tests to verify battle flows, overworld navigation, and menus operate correctly after the migration.
- Use Unity's Test Runner or `UnityTest` attribute for edit-mode tests where possible.
- Profile the project with the Unity Profiler to confirm that asset upgrades do not regress performance.

## 6. Follow-Up Work
- Update the build pipeline (CI/CD) to use Unity 6 CLI build commands.
- Refresh documentation and screenshots to reflect the new UI implementation.
- Re-export asset bundles or addressables generated by previous Unity versions.

> **Note**: Completing this migration requires a full Unity editor session and cannot be performed purely through script modifications in this environment. Use this document as a roadmap when performing the upgrade locally.
